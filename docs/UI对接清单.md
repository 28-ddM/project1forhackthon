## 二、四条红线：这些动了就白干

这个项目是单文件应用，界面和逻辑挤在一起。所以：

### 1. 不要动 `<script>` 里的任何一行

`<style>` 结束到 `</html>` 之间那一大段是逻辑代码。它负责解析日期、存清单、调 AI、导出日历。改样式完全不需要碰它。

### 2. 不要删、不要改名任何 `id="...".`

JS 全靠这些 id 找到元素，删一个就是一片功能失效。现在一共 21 个：

```
input  run  clear  sample  pick  file  thumbs  inputCard
stats  result  tabs  ops  ics  copy  wipe
aibox  aiSum  aiKey  aiTest  aiRemember  aiStatus
```

### 3. 这 6 个 class 是 JS 动态生成的，改名字要同时改 JS

它们的元素不在 HTML 里，是运行后由脚本创建出来的。你在 CSS 里改了名字，脚本创建的还是旧名字，样式就套不上：

```
.item        每条待办卡片
.thumb       截图缩略图
.tag         材料小标签
.group-title 分组标题（3天内 / 一周内…）
.empty       空状态提示块
.ai-sum      折叠标题上的「已就绪」小字
```

顺带说：`.item` 还会叠 `g-urgent` / `g-soon` / `g-far` / `g-over` / `g-nodate` 来表示紧急程度，这些名字也不能改。

### 4. 不要拆掉 `<details>` / `<summary>` 的折叠结构

「AI 概括」那一块是靠 `<details>` 实现展开收起的，而且脚本里会主动把它展开（`$aiBox.open = true`）。换成 div + 手写 toggle 就和逻辑打架了。

## 三、你最该改的地方：`:root` 里的颜色变量

`<style>` 开头有一整段 `:root { ... }`，那是全站配色。**改这里的值，整个页面跟着变，而且绝对碰不到逻辑。**

现在是这样：

```css
:root {
  --ink: #1a1a1a;          /* 主文字、主按钮底色 */
  --ink-2: #333;           /* 次一级文字 */
  --muted: #666;           /* 说明文字 */
  --muted-2: #888;         /* 分组标题 */
  --muted-3: #555;         /* 标签文字、折叠标题 */
  --src: #777;             /* 原文出处那段小字 */
  --faint: #999;           /* 辅助 / 占位 / 已完成 */

  --line: #e0e0e0;         /* 卡片描边、分隔线 */
  --line-2: #ccc;          /* 输入框与按钮描边 */
  --line-3: #ddd;          /* 事项卡片左边框、缩略图框、空状态虚线 */

  --bg: #f4f4f4;           /* 页面底色 */
  --surface: #fff;         /* 卡片底色 */
  --surface-2: #f7f7f7;    /* 浅底块（原文出处、提示条） */
  --surface-3: #fafafa;    /* 已完成项底色 */
  --tag-bg: #f0f0f0;       /* 材料标签底色 */

  --danger: #c0392b;       /* 紧急、删除、错误 */
  --danger-line: #e6b3ae;  /* 危险按钮描边 */
  --warn: #e0a800;         /* 一周内 */
  --ok: #1a7f37;           /* AI 就绪、成功 */
  --ok-line: #b7e0c3;      /* 就绪徽标描边 */
  --ok-bg: #f2fbf5;        /* 就绪徽标底色 */
  --link: #1a5fb4;         /* 链接 */

  --radius: 8px;           /* 大圆角 */
  --radius-sm: 6px;        /* 小圆角 */
}
```

**换一套配色的正确姿势**：只改右边那个十六进制色值。比如想做成深色主题，就让 `--bg` 变深、`--surface` 稍浅、`--ink` 变白——四个值一改，整站就换了。

⚠️ 两个注意：
- **别在变量定义里写 `var()`**（比如 `--ink: var(--ink)`），会死循环，整站变黑
- 改完注意**对比度**：`--ink` 和 `--surface` 之间要足够深，手机上太阳底下一照就看得出来

## 四、可以放开改的部分

| 能改 | 说明 |
|---|---|
| 字号、行高、字距 | 移动端基准 16px 起，别小于 13px |
| 间距、内距、圆角 | `--radius` 变量控制大圆角 |
| 布局 | 现在是最简单的单列流式，改成卡片网格也行，但**手机上不能出现横向滚动** |
| 按钮样式 | 主按钮是 `button.primary`，危险按钮是 `.ops .danger` |
| 字体 | `body` 的 `font:` 那一行 |
| 动画 | 加 `transition` 没关系，别加会拖慢首屏的大动画 |

**加新元素可以，但要遵守第 2、3 条**：新加的交互控件要么只做纯展示，要么先和写逻辑的人说一声，让他给你绑事件。

## 五、现在已知的三个短板（如果你有时间，这些最值得改）

1. **顶部信息薄**：「截止日雷达」只有一个标题 + 一行副标题，答辩投屏时第一眼不抓人。可以加个副标题徽章或一句 slogan。
2. **空状态太素**：「清单还是空的。先粘几条群通知试试。」——纯文字，没有引导感。可以加个示意图或更明确的箭头指向输入框。
3. **危险按钮不够区分**：「清空全部清单」和「复制成清单」现在长得差不多，误点代价很大。

## 六、改完必须自测这 6 件事

**用手机测，不是电脑。** 电脑上好看不代表手机上好看。

- [ ] 1. 打开页面，输入框、按钮显示正常，**没有横向滚动条**
- [ ] 2. 点「填入示例」→「分析并加入清单」，能出 4~6 条待办
- [ ] 3. 每条待办左侧竖条颜色不同（红 / 黄 / 绿 / 灰），能分清紧急程度
- [ ] 4. 点待办的勾选框，能打勾、文字变灰划线；点右侧 `×` 能删掉
- [ ] 5. 点「图片选取」，能调起相机 / 相册；选一张图后出现缩略图，能点 `×` 删掉
- [ ] 6. 点「下载日历文件 .ics」，能下载（微信里打开会失败，用系统浏览器测）

六条全过，再交回。

## 七、怎么把成果交回来

**首选：直接改仓库里的 `index.html`。**

```bash
git pull
# 改 index.html
git add index.html
git commit -m "[ui] 说明你改了什么，一句话"
git push
```

commit 说明写清楚改了什么，比如 `[ui] 主色换成蓝色，按钮圆角调大`。不要写 "update" 或者 "改了一下"。

**如果 git 用不顺手**：把你的 `index.html` 直接发到群里，说一句「我改了样式，没动 script」，由技术负责人合并。**千万别同时两个人改同一个文件再各自 push**，会冲突。

---

## 八、一句话总结

> **你只管 `<style>` 里的事。`<script>` 一个字都别碰，21 个 id 一个都别删，6 个动态 class 一个都别改名。**

守住这句，怎么改都不会把功能改坏。
