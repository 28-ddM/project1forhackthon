## 提示词正文（从下一行开始整段复制）

你是一名擅长「克制型」界面设计的资深前端，现在要改造一个已经完整可用的单文件网页产品的视觉层。请先读完全部要求再动手，不要急着改代码。

### 一、产品是什么

「截止日雷达」——把班级群、社团群里杂乱的聊天通知，解析成一份不会错过的截止日清单。

用户场景很具体：大学生在群里收到「下周五 18:00 前交实验报告」「周三前填报评教」这类消息，一刷就忘。这个工具让人把整段群消息粘进来，自动拆成一条条待办，按紧急程度分类，还能导出成日历文件。

两个不可动摇的产品卖点：
1. **断网也能用**（不填 API Key 时走本地规则引擎）
2. **数据不上传**（全部存在浏览器本地）

### 二、技术前提（这些不满足，改了就白干）

这是一个**单文件应用**：`index.html` 里 HTML、CSS、JS 全部内联，双击就能在浏览器打开。

因此：

- **禁止引入任何外部依赖**。不许加 Tailwind、Bootstrap、任何 CDN、任何 npm 包、任何 Google Fonts、任何图标库。一个 `<link rel="stylesheet">` 都不能新增。理由不是懒，是断网时样式会全丢，而「断网可用」是核心卖点。
- **只能改 `<style>` 段和 `<body>` 里的视觉结构**。`<script>` 标签里的内容**一个字都不许动**——那是解析、存储、调 AI、导出日历的全部逻辑。
- **不许拆成多个 HTML 文件**。脚本开头是一批 `getElementById`，元素不在同一份文档里就返回 `null`，所有按钮会瞬间失效。
- **不许加 `alert()` / `confirm()`**。页面已经有自研的轻提示 `toast()` 和确认框 `ask()`，样式跟主题走。

### 三、绝对不能碰的东西

**1. 以下 56 个 `id` 一个都不能删、不能改名、不能移到别的元素上**（JS 全靠它们找元素）：

```
三屏骨架   screen-mode  screen-app  screen-cal  topnav
顶部导航   navMode  navHome  navCal  navGuest
模式屏     modeGrid  modeGo  connectBox  connGrid
           customUrlRow  customUrl  modeKey  modeRemember
           verifyBtn  verifyStatus  fallbackBox  fallbackMsg
           fallbackLocal  fallbackRetry
输入区     input  run  clip  clear  sample  pick  file  thumbs  inputCard
清单区     stats  result  tabs  ops  ics  copy  wipe  localNote
AI 面板    aibox  aiSum  aiKey  aiTest  aiRemember  aiStatus
日历屏     weekBar  weekTitle  weekPrev  weekNext  calFilter  calList
提示确认   toastWrap  mask  dlgText  dlgYes  dlgNo
```

**2. 以下 class 是 JS 运行时动态创建的**，改了名字样式就套不上，必须原样保留：

```
.item         单条待办卡片（工作台与日历共用）
.thumb        截图缩略图
.tag          材料小标签
.group-title  分组标题
.empty / .empty-msg / .mascot   空状态
.ai-sum       折叠标题上的状态小字
.toast        轻提示
.dialog       确认框
.day-cell     周历格（叠加 .today / .pick / .dim 三种状态）
.dots i       周历格下的截止日圆点
```

`.mode-card`、`.conn-card` 的**选中态 class 是 `.on`**，由脚本切换，不能改名；`.mode-card` 右下角那个对勾靠 `.on` 控制 `opacity` 显隐。
`.local-note` 靠 `hidden` 属性控制显示，**不要改成 `display:none` 的内联样式**。
`.item` 会叠加 `g-urgent` / `g-soon` / `g-far` / `g-over` / `g-nodate` 表示紧急程度，**卡片左边框的颜色专门留给紧急度**，hover 只能动另外三条边。

**3. 空状态插图是 base64 内联在 JS 常量里的**，不要删、不要换成外链图片、不要替换成 emoji。

**4. `<details>` 折叠结构不能拆**（`#aibox` 是 AI 面板，靠原生 `details/summary` 展开收起）。

### 四、这次要做什么（核心诉求）

三个词：**更简洁、更有奶龙味、排版可以大改**。

**① 简洁**

当前界面信息密度偏高，很多卡片里塞了 3~4 层文字（标题 + 说明 + 提示 + 备注）。请按这个顺序做减法：

- 每张卡片只保留**一个**主标题 + **一段**说明。次要信息（操作提示、补充说明）降级成更小的字号，或收进需要时才出现的位置。
- 首屏不要一上来就给两个大段说明文字。让人一眼看懂「这是干嘛的」+「点哪个按钮」就够。
- 减少同时出现的边框、底色、分隔线。层级靠留白和字重建立，不靠画框。
- 数字和状态要突出（比如「3 天内 · 2 条」这类信息应该比说明文字更醒目）。

**② 奶龙元素**

奶龙是一个圆润、暖黄、表情憨厚可爱的卡通形象。要的是**气质**，不是把图片铺满页面：

- 主色延续暖黄（`#f0b429` 一系），配奶白卡片、暖米色页面底。整体像一个「奶油蛋糕」而不是「办公软件」。
- 形状语言：大圆角、圆润的胶囊标签、柔和的描边。避免尖锐直角、避免硬阴影。
- 可以用**极简的手绘感线条**表达奶龙气质（比如圆头圆脑的图标、弯曲的弧线、小小的表情符号），但**必须用内联 SVG 或纯 CSS 画**，不能引入图片文件或图标库。
- 现有两张托腮插图已经内联好了，只在「清单为空」时出现。可以调整它的大小和位置，但不要放大成背景图，不要加白底方块。
- 动效要「憨」：缓慢的呼吸、轻轻的位移。**禁止弹跳、抖动、旋转、粒子、发光**。

**③ 排版可以大改（这是本次最大的自由）**

你**可以**重排整个页面的布局结构：

- 调整 `<body>` 里元素的顺序、容器层级、卡片的分组方式
- 改变首屏的组织方式（现在是「标题 + 副标题 + 说明 + 卡片」，可以换成更聚焦的单卡、分步引导、或者上下分区）
- 改导航形态（现在是顶部一行三个按钮，可以做成分段控件、底部 Tab、或者更轻的胶囊条）
- 改网格列数、改桌面宽屏的版式（现有 `@media (min-width: 900px)`，可以继续加宽屏布局）
- 改按钮的层级关系（主次按钮的视觉权重可以重新设计）

但重排时必须守住第三条的三条底线：**id 都还在、动态 class 名不变、不拆文件**。

### 五、建议保留的设计基因

这些是已经调好的，改之前想清楚为什么要改：

| 项 | 现状 |
|---|---|
| 圆角 | 只有两个值：卡片 16px、小控件 10px。别引入第三种 |
| 阴影 | 全站唯一 `0 1px 2px rgba(58,51,44,.07)`。禁止重阴影、多层阴影、发光 |
| 过渡 | 统一 `200ms ease` |
| 栅格 | 8px 基准，间距取 8 / 16 / 24 |
| 交互 | hover 只加深边框或变暗，不放大、不上浮、不弹跳 |
| 配色 | 定义在 `:root` 的 CSS 变量里，改值全站生效。**不要在变量定义里写 `var()` 自引用**，会循环引用导致整站变黑 |

### 六、三个最值得优先解决的短板

如果时间有限，按这个顺序做：

1. **危险按钮不够吓人**：「清空全部清单」和「复制成清单」长得太像，误点代价很大。只改样式即可，比如给它 `--danger` 描边 + 极浅红底，不要动结构。
2. **模式入口太隐蔽**：导航右侧的「模式」按钮是回选择页的唯一入口，现在和「首页 / 日历」长得一模一样。可以加一个状态小圆点（本地=灰、AI 已接入=绿），让人一眼看出当前跑在哪套引擎上。
3. **待办卡片信息层级平**：标题、日期、出处、标签几乎一样重。建议让「截止时间」成为视觉焦点，其他信息退到第二层。

### 七、交付前必须自测

**用手机宽度测，不要只看电脑。** 在浏览器开发者工具里把宽度调到 375px，逐项确认：

- [ ] 页面**没有横向滚动条**（这一条最容易翻车，改布局时特别注意）
- [ ] 首屏能看到两张模式卡，本地卡默认选中（暖黄描边 + 对勾）
- [ ] 点「用本地模式开始」能进工作台，导航显示「本地模式」
- [ ] 点「AI 模式」时接入区能展开；点「改用本地模式」能正常进入
- [ ] 工作台里输入框和 5 个按钮完整可见，不换行错位
- [ ] 点「填入示例」→「分析并加入清单」，能出待办并按紧急程度分组
- [ ] 切换「待办 / 已完成 / 全部」三个 tab 正常
- [ ] 点「日历」能进周历屏，七个日期格不挤爆，今天有高亮
- [ ] 点「清空全部清单」弹出的是页面中间的白色确认框，不是系统黑框
- [ ] 桌面宽度（1100px 以上）下布局不塌，也不出现大片空白

### 八、输出要求

1. 优先给**完整的 `index.html`**（因为结构可能重排）。如果改动集中在样式，也可以只给 `<style>` 段 + 说明改了哪些结构。
2. 附一段简短说明：改了哪几块、为什么这么改、哪几处做了取舍。
3. 不要为了好看而新增功能。**这次只做视觉，不加新交互**。

### 九、最后一句

如果某处改动会让你不得不改 `<script>`、删 `id`、或者引入外部依赖，那就**放弃这个改法**，换一个视觉手段实现同样的效果。

## 改完怎么交回来（给 lfl）

1. 解压 `截止日雷达-给lfl-最新.zip`，用 VS Code 或任何编辑器打开 `index.html`
2. 只改 `<style>` 段和 `<body>` 结构，`<script>` 保持原样
3. 用浏览器直接双击打开测（`file://` 就能跑，不需要服务器）
4. 按上面第七节自测，重点是 375px 宽度下不能有横向滚动
5. 把 `index.html` 单独发给技术负责人，附一句「改了 style + 某几块结构，没动 script」

**不要自己 `git commit`**：本地仓库的代码比 GitHub 上的新，直接提交会打架。发文件最稳。
