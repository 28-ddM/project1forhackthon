## 一、先解决一个硬伤：现在是单文件

当前仓库只有**一个** `index.html`（约 24KB，结构 / 样式 / 逻辑全在里面）。

**单文件 = 只能一个人改。** 三个人同时动它，必然互相覆盖，而且 Git 无法帮你合并 HTML 里的混排代码。

**今天就拆（20 分钟，超时就退回时间段独占）：**

| 文件 | 内容 | 归属 |
|---|---|---|
| `index.html` | 只留结构 + 引用，改前在群里报备 | lfl |
| `style.css` | 全部样式 | lfl |
| `ui.js` | `render` / 渲染与状态 | lfl |
| `app.js` | `parseWhen` / `extract` / `doIcs` / `run` | 你 |

**三条技术红线（拆完必须仍然成立）：**
1. 不用 `type="module"` —— `file://` 下会被浏览器拦成白屏
2. 不用任何 CDN —— 断网就废，断网演示是核心卖点
3. 主流程不发网络请求 —— 网络只服务"接大模型"这一个加分项

**拆不动的退路**：保持单文件，按时间段独占（例如 12:00–15:00 归 lfl 改样式，15:00–18:00 归你改逻辑），中间只说话、不动手。

## 三、提交与同步（零基础照做）

**每次开工前，先拉最新代码：**
```bash
git pull
```

**改完，提交并推上去：**
```bash
git add -A
git commit -m "[fix] 修了日期解析：本周五 18:00 现在能识别"
git push
```

**commit message 格式**（一句话说清改了什么，别写"update"）：

| 前缀 | 用在 |
|---|---|
| `[feat]` | 加功能 |
| `[fix]` | 修 bug |
| `[style]` | 只改样式、不动逻辑 |
| `[docs]` | 只改文档 |

**频率：每完成一个小功能就 push 一次，最长不超过 2 小时。**
不要攒到晚上——最后两小时的合并冲突比写代码更耗人。

## 四、四条禁令

1. **不两个人同时改同一个文件。** 改别人的文件前先在群里说一句。
2. **不把 API Key 写进代码。** 仓库是公开的，提交后几秒就会被爬走；写进历史记录删了也没用。Key 只存浏览器 localStorage，或走那个折叠的输入框。
3. **不在冷场时换技术路线。** 换栈的决定只能在 11.07 14:00 前做，之后把现有方案做完。
4. **11.07 19:00 之后不加功能。** 任何人提新需求，记到 v2 清单，不实现。11.08 09:00 起只修 bug、只改文案。

## 五、冲突了怎么办（不要慌）

如果 `git pull` 出现 `CONFLICT`：

1. **不要乱删文件**，不要执行 `git checkout -- .`（会丢掉你自己的改动）
2. 在群里发一句"我冲突了，在改 xxx 文件"，让另一个人先停手
3. 打开冲突文件，搜索 `<<<<<<<`，保留正确的那段，删掉 `=======` 和 `>>>>>>>` 标记
4. `git add -A` → `git commit -m "[fix] 解决冲突"` → `git push`
5. 改完立刻刷新浏览器，确认页面还能跑

**兜底**：**Git 历史本身就是备份**，不需要手动复制文件。任何时候想回到某个版本：

```bash
git log --oneline          # 找到想回去的那次提交
git checkout <commit> -- index.html   # 只恢复这一个文件
```

所以只要坚持"每完成一个小功能就 commit"，就不会出现"改坏了没法回去"的情况。
