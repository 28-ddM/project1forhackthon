# 截止日雷达 · 产品需求文档（PRD v1.0）

> 中源黑客松 · 河南大学站（HENU HACK 2026）｜赛道 02 AI × EFFICIENCY 效率革命  
> 版本：v1.0 ｜ 日期：2026-11-07 ｜ 状态：开发中

---

## 0. 一句话

**把微信群里的截止日，变成你手机上真的会响的日程。**

---

## 1. 问题

不是"截止日没人通知"，而是**通知发过了，但它埋在几百条消息里**。

一个学期的真实场景：

- 通知分散在 12 个群：班群、社团群、课程群、学生会群、宿舍群、竞赛群
- 一条通知里可能藏着三件事："本周五交汇总表、下周三开会、月底前交读书笔记"
- 班委转发时套了三层前缀："【学工办】【转】【重要】关于……的通知"
- 错过一次的代价不是"少看一条消息"，是**挂科、失去资格、错过报名**

学生的实际应对方式是：截图存相册、抄进备忘录、靠脑子记。**这三种方式最后都会忘。**

## 2. 用户

**主要用户**：每学期要在 10 个以上群里追通知的在校大学生，尤其是班委、社团干事、竞赛参与者。

**他们的特征**：

- 不会为此装一个 App，也不会注册账号
- 电脑上会看群（PC 微信可直接拖选文字复制），手机上也看
- 真正需要的是"别忘了"，不是"整理得好看"

**非目标用户**：职场人士（已有 Slack/飞书/Outlook 生态）、企业行政（需求是审批流，不是提醒）。

## 3. 核心洞察

**截止日这个信息从来不存在缺失问题，存在的是"落地"问题。**

从"群里发过"到"我按时交了"，中间有四个动作：

```
看到 → 记住 → 设提醒 → 到点被提醒
```

现有工具全都卡在后两步：

| 环节        | 现状             | 谁解决了       |
| --------- | -------------- | ---------- |
| 看到        | 消息太多，漏看        | 腾讯元宝能总结群聊  |
| 记住        | 靠脑子，必忘         | 备忘录能记，但没人记 |
| **设提醒**   | 要手动打开日历、新建、填日期 | **没人做**    |
| **到点被提醒** | 依赖上一步          | **没人做**    |

**我们只做后两步。** 这是"最后一公里"，也是大厂不做的部分——因为大厂要你留在它的生态里，而我们要把你送出到系统日历。

## 4. 产品定义

**做什么**：把一段群消息文本，转成结构化的截止日清单，并一键写进手机系统日历。

**不做什么（以及为什么）**：

| 不做          | 原因                                      |
| ----------- | --------------------------------------- |
| 读微信/QQ 聊天记录 | 技术上需解密本地库；合规上涉及群内其他成员个人信息；演示时无法在评委电脑上复现 |
| 登录注册        | 评委不会为了看作品去注册；24 小时内做不完                  |
| 后端 / 数据库    | 数据留在用户浏览器里，不用上传，也不用承担隐私责任               |
| 小程序 / App   | 审核、打包、签名，任何一项都能吃掉一整天                    |
| OCR / 图片识别  | 必须联网调模型，会砍掉"断网也能演示"这个唯一硬优势              |

**一句话边界**：**只要还停留在"输入文字、输出结果"，就只做网页；任何需要联网才能启动的功能，一律不做。**

## 5. 使用模型（本产品的关键设计）

**它不是一次性转换器，是一个会累积的清单。**

### 错误的模型（大部分同类工具）

```
攒一周通知 → 一次性倒进去 → 看结果 → 关掉 → 下周重新来
```

问题：每次使用都是一次"大动作"，用户坚持不了三次。

### 我们的模型

```
看到一条通知 → 顺手粘一下（10 秒）→ 它进入我的清单 → 关闭
```

三个配套设计：

1. **追加，不覆盖**：新解析的条目追加到本地清单，旧的不动
2. **有"全部"视图**：页面显示"本学期 12 条 · 3 条待办 · 2 条已过期"，而不是"本次结果"
3. **能勾完成**：做完的打勾，从待办里消失，但记录保留

**这一条决定了产品是"工具"还是"日常用品"。** 有"完成"概念，用户才会反复打开。

### 使用频率的现实预期

- **开学第一周**：集中录入一次（10–20 条）
- **之后每周**：打开 1–2 次，粘 1–2 条，勾掉做完的
- **考前**：翻一遍清单

## 6. 功能规格

### P0 — 三个，缺一个就算没做完

| # | 功能     | 完成标准                            | 卡点    |
| - | ------ | ------------------------------- | ----- |
| 1 | **解析** | 粘 10 条真实群通知，≥7 条抽对（事项/日期/材料都正确） | 12:00 |
| 2 | **呈现** | 时间轴按天排开，3 天内标红，每条可看原句           | 16:00 |
| 3 | **落地** | `.ics` 能导入手机日历并带提前提醒；能复制成文本     | 19:00 |

### P1 — P0 全绿才允许碰，按顺序

| 顺序 | 功能              | 成本     | 价值           |
| -- | --------------- | ------ | ------------ |
| 1  | 累积清单（追加/勾完成/总数） | 2 小时   | 决定产品形态，优先级最高 |
| 2  | 剪贴板读取按钮         | 10 分钟  | 手机端省掉一次长按粘贴  |
| 3  | AI 增强解析（失败静默回落） | 1–2 小时 | 技术分          |
| 4  | 手机端适配           | 1 小时   | 评委扫码要能自己跑通   |
| 5  | 公网部署更新          | 15 分钟  | 链接不变，内容最新    |

### P2 — 有余力才做

图片/截图入口（2–3 小时，必须联网）、场景示例切换、深色模式、动效。

### 明确不做

登录注册 · 读聊天记录 · OCR API · 小程序/App · 多端同步 · 多人共享清单 · 语音输入。

## 7. 交互流程

### 首次使用

```
打开页面 → 看到一句"粘贴群消息，自动变成截止日清单"
→ 点「填入示例」（可选，用于理解）
→ 粘贴自己的群通知 → 点「分析」
→ 看到时间轴 + 条目卡片
→ 点「下载日历文件 .ics」→ 手机/电脑弹出"添加到日历"
→ 完成
```

### 日常使用

```
复制一条通知 → 打开页面（可加到桌面主屏）→ 粘贴 → 分析
→ 新条目追加进清单 → 关闭
```

### 三种必须存在的状态

- **空状态**：没输入时提示"粘贴几条群通知"，不是一片空白
- **处理中**：点了立刻有反应（转圈 + 文案），不能卡住不动
- **错误**：说清楚为什么（"没找到像『什么时候要做什么』的句子，试着带上时间词"）

## 8. 数据契约（12:00 冻结，之后不许改）

```js
// 一条待办
{
  id: "1723456789012",        // 时间戳生成，用于追加去重
  title: "交创新学分汇总表",   // 事项
  due: "2026-11-13",          // YYYY-MM-DD，无则 null
  time: "18:00",              // HH:MM，无则 null
  materials: ["汇总表"],       // 要交的材料
  source: "【学工办】请各班班长于下周五…", // 原文出处
  days: 6,                    // 距今天数，无日期则 null
  level: "soon",              // urgent(≤3天) / soon(≤7天) / "" / nodate
  done: false                 // 是否已完成
}
```

**DOM 五件套**（改 id 会导致页面白屏，改前必须报备）：  
`#input` `#run` `#clear` `#sample` `#result`

**函数边界**：

- `extract(text) → items[]`：纯函数，不碰 DOM，可单独测
- `render(items)`：只负责画，不改数据
- `doIcs(items)`：生成文件
- `run()`：唯一把三者串起来的地方

## 9. 技术架构

**形态**：纯前端单页应用。一个文件夹，双击 `index.html` 就能跑。

```
用户浏览器
├── HTML + CSS      页面长什么样
├── JavaScript      解析、渲染、生成 .ics
├── localStorage    保存清单（数据不出本机）
└── 无后端、无数据库、无账号
```

**抽取两层**：

- **规则引擎**（本地，断网可用）：日期/周次/时间/材料的模式匹配
- **大模型**（可选）：提升"下周三前""月底之前"这类歧义表述的准确率
- **失败、超时、CORS 被拦 → 静默回落规则模式**，界面不报错，只标记"本地模式"

**三条技术红线**：

1. 不用 `type="module"`（`file://` 下会白屏）
2. 不用任何 CDN（断网即废）
3. 主流程不依赖网络请求

## 10. 竞品与差异

| 产品                  | 做到哪             | 差在哪                       |
| ------------------- | --------------- | ------------------------- |
| 腾讯元宝                | 微信群聊 → 纪要 + 待办  | 出的是纪要，不是能落地的清单；必须联网；不导出日历 |
| Coze「群待办不漏事」        | 粘贴群聊 → 待办 + 责任人 | 纯提示词，无界面、无导出、不进日历         |
| Motion / Todoist AI | 邮件、Slack 抽任务并排期 | 全英文、面向职场、要订阅              |
| Aemeath Bot（开源）     | QQ 群 → 自动写进手机提醒 | 需要常开电脑 + NapCat，普通学生部署不了  |

**我们的位置：最后一公里。**

> 别人做"帮你总结"，我们做"帮你被叫醒"。

**如果被问"元宝不是能总结群聊吗"**：

> "能，但它出的是纪要，你还得自己记下来、自己设提醒，而且必须联网。我们更窄：粘贴、出清单、导进你手机日历，断网也能跑。我们不做平台，只做最后一公里。"

**如果被问"为什么不直接读聊天记录"**：

> "能做，技术上就是读本地加密数据库。但群里的消息是几十个人的，不是用户一个人的，没经过同意就采集处理，这个我们不愿意做。所以我们的设计是：用户自己决定粘什么进来，数据不出浏览器。"

## 11. 验收标准

一份作品算"做完了"，必须同时满足：

1. **拔掉网线**，双击 `index.html`，粘贴示例，能出结果、能导出 `.ics`
2. **陌生人不看说明**，30 秒内能自己用起来
3. **一句话讲完**："把群里的截止日变成手机日程"，不需要第二句解释
4. **`.ics` 导进手机后**，日历里真的有这一天，且提前 12 小时提醒
5. **10 条真实语料**，≥7 条抽对

## 12. 风险与对策

| 风险               | 概率 | 对策                                   |
| ---------------- | -- | ------------------------------------ |
| 日期解析不准（"下周三"歧义）  | 高  | 规则引擎兜底 + 无日期条目单列"需人工确认"，不假装抽对        |
| 浏览器直连大模型被 CORS 拦 | 中高 | 20 分钟验证；不通就只保留规则层，AI 用录屏演示并如实说明      |
| 三个人的文件互相覆盖       | 中  | 主副本只有一份；样式走整文件交接；每跑通一个功能另存版本号        |
| 时间不够             | 中  | 19:00 后不加功能，只修 bug；P0 优先于一切加分项       |
| 现场投影看不清          | 中  | 正文 ≥16px、标题 20px 起、单色强调、高对比，不用渐变和细边框 |
